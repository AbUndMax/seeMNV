# seeMNV
in-codon Multiple Nucleotide Variant detector for GATK derived Multisample VCF files.

This tool is an extension and Java translation of the python tool codonMNV which is part of the master thesis:
> Large-scale characterization of intraspecific variation in outer membrane proteins of *Treponema pallidum*

Written by N. M. Gerbes
at the Institute for Bioinformatics and Medical Informatics, University Tübingen, 15.05.2026

A detailed description of the tool can be found in the thesis section 3.2: "Implementation of codonMNV for in-
codon MNV detection"


## Overview

Standard variant annotation tools may fail to identify in-codon MNVs in multi-sample VCF files when variants are represented as separate SNV entries. `codonMNV` addresses this by evaluating sample-specific genotype information directly from the VCF genotype fields.

For each codon, the tool collects all SNVs located within the three codon positions and tests whether at least two affected codon positions are present in the same sample. Valid combinations are emitted as additional cMNV entries while preserving all original VCF entries.

## cMNV Definition

An in-codon MNV (cMNV) is defined as a set of two or three SNVs located at distinct positions within the same codon and therefore present in the same chromosome and sample.

For each sample, a variant is considered present if the genotype value indicates at least one alternative allele. Genotypes equal to `0` or non-numeric genotype values are treated as absent.

## Features

- Detects 2-base and 3-base in-codon MNVs.
- Processes multi-sample VCF files.
- Preserves all original VCF entries.
- Adds newly generated MNV entries to the output VCF.
- Aggregates sample-specific genotype fields conservatively.
- Supports multiple alternative bases at the same codon position.
- Adds metadata headers describing the command and the generated `cMNV` INFO field.

## Input requirements

`seeMNV` requires two input files:

1. A VCF file containing variant calls.
2. A coding sequence fastA file sorted ascending with a `[length=]` specifier in each sequence header.

The VCF file must fulfill the following requirements:

- Variants should be normalized with respect to the reference genome.
- Multiallelic records should be split.
- Per-sample genotype fields must be present from column 9 onward.
- The genotype format is expected to contain GATK-style fields such as:

```text
GT:AD:AF:DP:GQ:PL
```

Recommended preprocessing with `bcftools`:

```bash

bcftools norm \
  -f reference.fasta \
  -m -both \
  example.vcf \
  > example_normalized.vcf
```

## Usage

```bash
seeMNV [-h] -vp path/to/example.vcf -csp path/to/codingSequences.fna -o path/to/outFile.vcf
```

### Arguments

- `vcfPath`: Input VCF file containing gene-specific variant calls
- `codingSequencePath`: FastA coding sequences file
- `outPath`: Output path for the generated VCF file

## Output

The output is a new VCF file. **The original input file is not modified**.

The output VCF contains:

- all original VCF header lines,
- all original VCF entries,
- additional header lines generated by `seeMNV`,
- newly generated in-codon MNV entries.

Two additional header entries are added:

```text
##seeMNVCommand=
```

This stores the exact command used to run the tool.

```text
##INFO=<ID=cMNV,...>
```

This describes the structure of the generated `cMNV` INFO field.

## Generated MNV entries

For each detected in-codon MNV, a new VCF entry is generated.

The genomic position is set to the first affected position of the reported variant interval. The `REF` and `ALT` fields are set to "." while the values of the participating VCF entries can be found in the INFO string.

If variants occur at codon positions 1 and 3, the complete three-base interval is written, including the unchanged middle base.

## cMNV INFO field

Generated MNV entries contain a `cMNV` INFO field with the following pipe-separated structure:

```text
Num_alt_in_codon | Codon_idx_in_CDS | Original_codon | Variant_codon |QUAL_per_pos | FILTER_per_pos | affected_positions_genome | samples_with_alt_per_position| intersection_of_samples_with_alt
```

### Field description

- **Num_alt_in_codon**: Number of alternative variants combined into the MNV within the codon.
- **Codon_idx_in_CDS**: Index of the codon within the coding DNA sequence (CDS).
- **Original_codon**: Original codon sequence from the reference sequence.
- **Variant_codon**: Resulting codon sequence after applying all alternative alleles.
- **QUAL_per_pos**: The exact QUAL value of the respective VCF Entry from that pos.
- **FILTER_per_pos**: The exact FILTER value of the respective VCF entry from that pos.
- **Affected_positions_genome**: Genomic positions of the variants affecting the codon. `/` indicates an unaffected codon position.
- **Samples_with_alt_per_position**: Number of samples carrying the alternative allele at each codon position, reported separately for each ploidy component.
- **Intersection_of_samples_with_alt**: Number of samples carrying all alternative alleles involved in the MNV, reported separately for each ploidy component.

## Genotype field aggregation

For each generated MNV entry, sample-specific values are aggregated from the contributing SNV entries.

The following conservative aggregation rules are applied:

- `GT`: "requires equal" -> only if all VCF entries in that MNV for that sample had an 1 an 1 is written, else 0.
- `AD`: Minimum across contributing SNVs
- `AF`: Minimum across contributing SNVs
- `DP`: Minimum across contributing SNVs
- `GQ`: Minimum across contributing SNVs
- `PL`: Element-wise maximum across contributing SNVs

This strategy preserves the weakest support among the variants contributing to the MNV.
